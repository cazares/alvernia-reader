# DIMENSION: relay-protocol [unverified]
SUMMARY: The relay core is unusually well-defended for its size (zombie-CONNECTING timers, per-socket heartbeats, seq sanitization, durability-first publish, geo anti-brick fallbacks), and several map leads were confirmed already fixed (build 344/345 mitigations are real in code). The remaining holes cluster in four places: (1) director-side page authority is destroyed by any WebView reload/app restart — native adopts the web's boot page 2 and broadcasts it to the whole congregation, the single worst live-Mass failure found; (2) the web follower's seq guard runs BEFORE the freshness check, so over a healthy WebSocket a dead director is never demoted and a legitimately-regressed-seq takeover (worker allows it after 90s) is silently ignored; (3) the relay protocol has no transmitter identity, so two authorized publishers — including the public in-repo Sión code aimed at the live standard room — ping-pong every follower with no arbitration and no warning; (4) the default `npm run test:e2e` publishes real page flips into the production room. Medium findings cover interleaved async snapshot application during cross-book switches, wrong-song rendering for unauthorized followers under a green live pill, polling blind windows on WS-hostile networks, follower clock skew, and inflated fleet readiness.

### MEDIUM — relay-polling-stopped-before-ws-opens-blind-windows
